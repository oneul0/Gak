# 설계 문서 개선 봇 사용법

`docs/design` 문서를 문서 유형 분류, 정보 구조 개선, 문장 다듬기 순서로 개선합니다. 각 단계의 결과를 다음 봇에 전달합니다. 기술적 사실과 코드 예제는 보존하고, 문서의 목적에 맞춰 구조와 표현을 고칩니다.

## 봇 구성

| 순서 | 봇 | 정의 | 역할 |
|---|---|---|---|
| 1 | 문서 유형 정하기 | [document-type](../.claude/agents/document-type.md) | 읽기 전용으로 유형, 목표, 독자, 작성 지침을 정리합니다. |
| 2 | 정보 구조 만들기 | [document-structure](../.claude/agents/document-structure.md) | 개요, 제목, 정보 배치를 개선합니다. |
| 3 | 문장 다듬기 | [document-polish](../.claude/agents/document-polish.md) | 의미를 유지하며 문장과 용어를 다듬습니다. |

정의 파일은 Claude Code 프로젝트 에이전트 형식입니다. Codex 등 다른 도구에서는 각 파일의 지침을 작업 에이전트에 전달하고 같은 순서로 실행할 수 있습니다. 봇은 별도 서버나 외부 API를 호출하는 프로그램이 아닙니다.

## 실행 방법

Claude Code에서 [문서 개선 명령](../.claude/commands/improve-design-docs.md)을 실행합니다.

```text
/improve-design-docs
```

특정 파일만 개선하려면 경로를 전달합니다.

```text
/improve-design-docs docs/design/03_run_guide.md
```

문서에 별도 요구 사항이 있으면 경로와 함께 독자, 목표, 원하는 분량을 전달합니다. 실행 후 변경 내용을 검토합니다. 봇 실행 자체는 코드 예제나 명령어의 실제 실행 결과를 보장하지 않습니다.

## 기술 검증이 필요한 기존 내용

첫 번째 봇이 문서 사이에서 발견한 아래 차이는 문장 개선과 별도로 구현을 확인해야 합니다. 이번 편집에서는 어느 설명이 맞는지 추측하여 API 계약이나 동작을 바꾸지 않습니다.

- `03`과 `04`에 적힌 서비스 실행 순서가 다릅니다.
- `08`의 `X-Gak-Owner-Id` 전달과 `02`·`11`의 쿠키 인증 설명이 다릅니다.
- `02`와 `06`의 SSE 경로, `01`·`09`와 `11`의 LLM HTTP 경로 설명이 다릅니다.
- `10`의 전략 C에서 다른 `videoNo`를 조회하는 조건과 다른 채널을 조회한다는 설명을 구분해야 합니다.
- `12`에서 401을 예상하는 투표 세션 조회 API는 `06`에서 Public으로 표시되어 있습니다.
- `09`의 테스트 9개 통과 기록과 뒤쪽 테스트 목록은 작성 시점이 다를 수 있습니다.

이 차이들을 해소하려면 구현과 문서의 기준 날짜를 확인한 뒤 별도 수정합니다.
