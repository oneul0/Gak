description: 설계 문서를 문서 유형 분류, 정보 구조 개선, 문장 다듬기 순서로 개선한다.
---

사용자가 지정한 문서를 개선한다. 별도 경로를 지정하지 않았다면 `docs/design/*.md`를 대상으로 한다. 추가 요구 사항: $ARGUMENTS

다음 프로젝트 에이전트를 순서대로 사용한다. 이전 단계의 결과와 대상 파일 목록을 다음 단계에 전달한다.

1. `document-type`: 문서를 읽고 파일별 유형, 목표, 독자, 작성 지침을 정리한다. 원문에서 추론한 정보는 표시한다. 문서를 수정하지 않는다.
2. `document-structure`: 분류 결과를 바탕으로 개요, 제목, 정보 배치를 개선한다. 하나의 통합 개선안을 적용한다.
3. `document-polish`: 구조 개선 후 문장을 다듬고 문체와 용어를 통일한다. 조건과 예외, 기술적 의미를 보존한다.

이모지는 사용하지 않는다. 기존 파일명과 링크를 유지하고 기술적 사실, API 계약, 코드, 명령어, 수치, 날짜, 표의 데이터와 Mermaid 다이어그램을 보존한다. 문서 분리가 꼭 필요하면 링크와 목차를 함께 갱신한다. 없는 내용을 채우기 위해 구현 사실을 추측하지 않는다.

작업 후 변경 차이, 코드 블록, 링크와 제목 구조를 확인한다. 코드 변경이 없다면 서비스 테스트를 불필요하게 실행하지 않는다. 수정 파일과 주요 개선 사항, 확인한 항목과 검증하지 못한 항목을 보고한다.
